## Required outcome

Implement the owner/lead-approved experimental browser transport boundary and demonstrate two actual Outbreak/AssaultCube-derived browser client instances connecting to the actual separately running dedicated game server. This produces measured evidence for T015, not final production transport selection and not proof of authoritative Outbreak combat.

This draft deliberately does not select WebSocket, a gateway, WebRTC or WebTransport. Before release, a worker may submit a separately authorized proposal-only note, and the lead must freeze the chosen bounded experiment. A proposed schema is not authorization to implement it.

## Source evidence governing the experiment

- `source/src/client.cpp::connectserv_()` creates a native ENet host and peer, while `gets2c()` consumes ENet connect/receive/disconnect events and invokes normal client packet handling. Map peer lifetime, channel ID, reliability and packet ownership explicitly.
- `source/src/server.cpp::initserver(true)` creates the native host; its `serverslice()` handles host events. This process must remain the external server under test, with its real game packets and state.
- `source/src/server.cpp::localconnect()` creates an embedded `ST_LOCAL` administrative client; that path cannot substitute for the dedicated-server evidence. `client.cpp::disconnect()` can re-enter local mode and requires an explicit experimental policy.
- `source/src/protocol.h` defines existing wire messages; `server.cpp::buildworldstate()` and `sendworldstate()` assemble normal state traffic. Adapt delivery without silently changing authoritative behavior or inventing unrelated protocol semantics.
- `source/enet/unix.c` implements raw socket/DNS behavior. A generic TCP WebSocket proxy does not by itself bridge ENet's UDP protocol. Preserve datagram/message boundaries if the lead selects a gateway.

## Acceptance criteria after release

1. A repeatable command sequence builds the approved browser transport and standalone-server integration with recorded commit, toolchain, dependency, browser and OS versions. The handoff includes exact lifecycle cleanup steps.
2. Two distinct real browser client instances complete the actual game's server handshake and observe the same game/map and independently controlled actors through the standalone server. Provide session/actor IDs, normal packet-processing evidence and state comparisons. A synthetic echo server, fixture-only actor page, streamed native window or browser-local embedded server fails this criterion.
3. The adapter preserves the frozen packet framing, channel/reliability contract and buffer ownership. Invalid lengths, malformed frames and stale/duplicate session traffic are rejected according to the approved addendum without crashing peers or awarding gameplay effects.
4. Disconnect, page reload, reconnect attempt, timeout and server shutdown tests release resources. No orphaned session can continue sending as a previous actor, and fallback to offline local mode is explicitly distinguished from a remote reconnection.
5. Normal and approved impaired-network runs record actual latency/state-age/backlog, byte counts, queue high-water marks and errors. Queue bounds/backpressure are enforced. Report ordered-reliable delivery costs honestly; localhost success alone is not production shooter latency acceptance.
6. If a gateway is used, each browser session maps to its own approved game identity, packet boundaries are preserved, and requests cannot select arbitrary external destinations. The local gateway remains loopback-only and the test server never registers with public AssaultCube services.
7. Native client/server verification appropriate to affected shared files passes, or any unavailable check is explicitly NOT RUN and remains unresolved for lead acceptance. The report separates implemented transport, temporary adapters, simulated impairment and unimplemented Outbreak gameplay.
8. The worker submits a recommendation and measured tradeoffs for owner/lead review. The worker does not mark a production networking stack, T015 or P0 accepted and does not silently change engine, gameplay authority or product scope.
