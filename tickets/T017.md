## Frozen experimental behavior

These experimental technical parameters are approved by the lead for this ticket only, not amendments to game balance or final server simulation rules:

- Use `emscripten_set_main_loop` with browser-controlled frame cadence (`fps=0`) for the browser branch. Do not busy-loop or call `SDL_Delay` for browser frame limiting.
- The browser's local frame delta is bounded to 250 ms and reset on visibility/focus resume. For the OFFLINE_MAP experiment, the embedded local simulation deliberately follows this bounded local clock. This is not wall-clock standalone authority. Preserve native and separately running dedicated-server clock code; a future networked browser timing policy is outside this ticket.
- Movement/fire/jump held inputs are cleared when focus, visibility or pointer capture is lost. They remain clear until fresh input after a user-initiated return to play.
- Pointer capture is requested only through a user gesture; Escape/loss returns to an unlocked state and another user gesture is required to reacquire it. Do not hide a browser-denied request or repeatedly force capture.
- No new storage persistence or audio backend implementation is included. Identify those unimplemented startup/runtime concerns in the handoff.
