## Required outcome

Create an isolated, reproducible browser toolchain preflight and actual-engine compilation probe. Record the SDK identity and effective flags. Establish whether the candidate engine source parses and compiles to Wasm objects without host libraries. This work must not claim to produce a playable game or satisfy T014.

## Implementation boundaries

1. `preflight.py` checks for the chosen `emcc`/`em++` and companion tools, prints actionable missing prerequisites and exits nonzero when unavailable. It must not install dependencies or invoke package managers.
2. `probe-config.json` records the approved SDK version identity, include/port flags, explicit translation-unit list and output/cache locations. Do not select a moving `latest` SDK or silently update the lock.
3. `compile_probe.py` compiles `source/src/clientgame.cpp` as the client-side source probe. It may also compile `source/src/protocol.cpp` with `STANDALONE` as an additional diagnostic, but a standalone protocol object does not substitute for the client probe. No copied engine implementation or handmade substitute is permitted.
4. Browser-specific changes in `platform.h` are limited to target-dependent header selection necessary for the actual engine probe. Changes in `tools.h` are limited to a portable browser debug-assert trap. Keep native branches unchanged. New symbol stubs, disabled gameplay, rewritten engine headers and blanket warning/error suppression are outside scope.
5. Use target headers/libraries from the selected SDK or deliberately compiled target dependencies. Never use host framework binaries, native SDL config output or desktop GL/X11 linkage in the Wasm path.
6. Build outputs and cache writes must be isolated from native object/PCH/output files. Any unavoidable tool cache outside the approved locations requires a question before execution.

## Acceptance criteria

1. A clean environment without the SDK produces a precise missing-tool report and nonzero status; no source mutation, downloads or installs occur during preflight.
2. With the approved SDK available, the probe compiles the real `clientgame.cpp` to a Wasm-target object and records the command, exit code, compiler/SDK version, source identity, flags and diagnostic log. Compilation failure is reported as FAIL/BLOCKED, not replaced by a dummy source success.
3. The source probe runs in both release and `_DEBUG` configurations. A browser debug assertion uses a supported trap; native debug behavior is preserved.
4. Re-running the probe overwrites only its own generated output/cache paths. Native source-object outputs, pre-existing combat edits and other workers' files remain unchanged.
5. Generated result metadata clearly states `object_compilation_only`; it makes no renderer, linked-runtime, browser-session or network-success claim.
6. README gives exact preflight/probe commands, dependency acquisition boundaries, selected cache/output locations and the prerequisites that remain for T014.
