## Source revision versus generated metadata

Its strict SOURCE_INPUT_MANIFEST schema is in the candidate contracts: unique sorted canonical relative ordinary files with exact bytes/SHA256/mode420 or493, excluding the manifest itself. A commit cannot contain a manifest that self-references its own final Git hash. MAIN build metadata may accompany the clean checkout as a documented prerequisite; it does not authorize unknown source changes.

The source manifest and MAIN execution pins/decision are separate immutable release metadata. They must match actual checkout HEAD and file bytes, be supplied through the contract's fixed paths and have their expected SHA256 supplied separately. They cannot contain arbitrary executable commands, flags or environment overrides. A generated manifest or a green fixture suite never self-authorizes execution.
