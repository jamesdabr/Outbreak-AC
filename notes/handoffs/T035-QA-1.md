## 2. Proposed minimal data path and lifecycle

Browser NETWORK_CLIENT main frame polls pending transport state. A new logical
ENet socket starts an asynchronous WebSocket connection; `onopen/onmessage/
onerror/onclose` update only generation-tagged backend state and queues. On a
later frame, OPEN permits exactly one `enet_host_connect` to the frozen numeric
native address. Do not start the ENet attempt timer while waiting on WS opening,
and do not block the browser thread. `gets2c/c2skeepalive/flush` remain nonblocking.

One complete binary WebSocket **message** carries one unchanged ENet UDP datagram
in either direction, including ENet headers, compression flags, ACKs, channel
metadata and fragment commands. WebSocket framing/fragment reassembly belongs to
the inspected library/browser; it is not UDP fragmentation. No JSON, channel tag,
actor ID or arbitrary destination header is added to the datagram. ENet keeps
normal reliability, sequencing, fragmentation and parsing.

The gateway binds only `127.0.0.1:29865`; exact path `/enet`, proposed subprotocol
`outbreak-enet-dgram.v1`. Its fixed UDP destination is `127.0.0.1:29863`, configured
by lead-pinned run configuration, never by a browser message, URL or header. Each
accepted WS allocates a distinct connected UDP socket bound to 127.0.0.1 and an
ephemeral source port. Filter all receive traffic to the exact native target.
There is no LAN discovery, server-info forwarding, DNS, CONNECT method or general
TCP/UDP proxy. Gateway does not parse/rewrite gameplay packets or assign actor IDs.

Proposed session identity: fresh 128-bit run ID, 128-bit gateway session ID,
monotonic browser socket generation, unique native UDP tuple; logs correlate them
with native server clientnum/clientsequence after the real join. Use one-use
128-bit random join capabilities issued by the local supervisor, exact HTTP
Origin allowlist and exact path/subprotocol checks. Redact capability values from
logs. Reject null/wrong Origin, reused token, third active session and all extra
destination parameters before allocating UDP. No cookie/account credential is
used. Loopback is not by itself an authentication boundary against arbitrary web
pages or local software; this is a private process test, not production security.

On teardown, invalidate generation FIRST, stop queue admission, close WS and drop
owned JS buffers, reset peers/destroy host, clear remote players and remain
NETWORK_CLIENT/disconnected. Stale callbacks compare generation and their WS
object, and must never touch freed/reused Wasm handles. Explicit reconnect starts
a fresh host/WS/UDP identity; no automatic WS reconnect, resume token, actor reuse
or offline fallback. Existing ENet retransmits still operate inside a live session.

Clean ENet disconnect gets a bounded drain before closing WS; abrupt page reload,
gateway death or tab loss closes UDP forwarding and leaves native ENet to expire
the actual peer. The gateway cannot synthesize a valid game disconnect packet or
instantly delete a native actor without a separately approved server interface.
Quarantine retired UDP source ports for the proposed period below to reduce
delayed datagram crossover; retained quarantine sockets consume the retired cap
and discard everything. ENet connectID/session checks remain necessary, not a
substitute for generation checks. No old bytes are replayed into a new session.

### Buffer ownership and socket API proposal

- **Send:** validate total vector length/overflow and target tuple, gather into a
  newly allocated JS-owned Uint8Array before returning to C. Cache no HEAPU8,
  ENetBuffer pointer or caller packet backing store. Reacquire current memory view
  on every immediate bridge call because memory can grow. Successful return means
  the complete copied datagram was accepted into the bounded WS send path, not
  delivered/acknowledged by native ENet. No partial-length success is permitted.
- **Receive callback:** require ArrayBuffer binary data, validate length/session,
  copy into an owned queued buffer. Blob/text/control frames are not datagrams.
  Do not call Wasm parser, game callbacks or malloc using a stale heap view from
  an asynchronous callback. Dequeue during `enet_socket_receive`; check combined
  destination capacity then copy once into the current Wasm buffers and fill the
  fixed server ENetAddress. No truncated prefix may become a valid datagram.
- **Backpressure:** if not OPEN, over limit, stale, invalid target or send throws,
  latch a terminal transport error, reject the datagram (−1), then perform explicit
  frame-owned teardown. Do not return 0 as a pretend ENet retransmit queue, mutate
  ENet reliable flags or selectively drop “unreliable” raw datagrams: one datagram
  can contain mixed commands. Only declared impairment mode drops whole datagrams
  with a recorded reason/seed.
- **Other platform functions:** browser-only unit supplies initialize/deinitialize,
  monotonic millisecond `enet_time_get/set` with ENet's 32-bit wrap conventions,
  numeric-only address set/get formatting, logical datagram create/destroy,
  receive/send and readiness. No raw native socket or DNS calls. NONBLOCK=1 is
  real nonblocking mode. RCVBUF/SNDBUF map to bounded queue capacities, explicitly
  documented; BROADCAST/listen/accept/stream/native connect are unavailable with
  actual failure returns. Host ignores some option results, so record rejected
  options rather than claiming broadcast support. `wait(timeout=0)` reports current
  readiness without sleeping; nonzero waits fail visibly. Audit/export
  `socketset_select` too; never emulate a blocking success. Retain Unix code for
  native target and original browser OFFLINE_MAP until separately rebuilt.

### Additional ENet allocation blocker

`enet/include/enet/protocol.h` permits a 1 GiB reassembled packet and 1,048,576
fragments; `protocol.c` reliable/unreliable fragment handlers allocate using the
declared totalLength after those checks. A 4096-byte raw-message cap does **not**
bound reassembled memory. The default allocator's no-memory callback is `abort`
(`callbacks.c`). It is unsafe to call a transport ring bounded while ignoring this.

Propose browser NETWORK_CLIENT-only policy: ≤64 KiB reassembled packet, ≤128
fragments/message, ≤1 MiB total pending reassembly per peer and ≤8 MiB total ENet
allocations/retained packets per browser session. Enforce before fragment-table/
payload allocation and account releases/reset/logger retention. This needs an
explicit separately owned ENet hardening decision/ticket (`protocol.c`, `peer.c`
and possibly headers/allocator accounting), not a silent global protocol constant
change in the socket backend. Preserve native wire/parser behavior outside the
experimental guard. Oversize reassembly is a visible profile rejection, not a
fake OOM success; required map/demo downloads stay excluded and preloaded assets
must suffice. A proposed allocator cap alone is not a proven recoverable rejection:
audit all NULL/error paths before claiming malformed traffic cannot abort peers.
If MAIN declines this scope, the untrusted/malformed bounded-memory acceptance
claim remains blocked; do not waive it based on loopback-only normal traffic.
