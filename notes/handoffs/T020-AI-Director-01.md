## Transitive startup, map and frame requirements

Existing startup is not a clean service boundary: main initializes ENet/client, calls initserver(false), creates an empty world, initializes rendering/audio/configs, loads server/package/auth configs and certificates, starts package updater, runs autostart/autoexec hooks, then localconnect. Server init config callbacks and static objects exist even without an ENet listening host. Merely excluding serverms.o, server.o, http.o or bots from a link will leave references from main, clients, menus, world loading, render and cleanup. CLIENT_OBJS in Makefile includes all of them; SERVER_OBJS uses STANDALONE variants and excludes bot modules.

The local protocol path is `localconnect -> addclient(ST_LOCAL/CR_ADMIN) -> sendservinfo -> sendpacket -> localservertoclient -> servertoclient/parsemessages -> SV_SERVINFO_RESPONSE -> sendpackettoserv -> localclienttoserver -> process -> auth queue -> serverslice/polldeferredprocessing -> completion/continued handshake`. Local `needsauth=false` is not equivalent to skipping the handshake. The existing worker explicitly succeeds a no-wantauth request; any offline replacement must preserve its caller-visible sequence and validation, not fabricate a remote welcome. Server sequence IDs guard stale completions.

For a real map, retain `empty_world`, graphics context/core texture/font setup, approved config/key bindings/model attributes, manifest media, `worldio::load_world` geometry/entities/textures/model/sound/collision preparation and `clientgame::startmap` player/map resets and spawn placement. `load_world` calls downloadpackages and c2skeepalive during loading; these need profile-aware behavior. It returns negative on load failure, positive warning bits on unresolved content, zero on clean load. Keep these distinctions visible. startmap sets map identity, resets bounce entities/flags, chooses spawn and conditionally initializes bots/local respawn. The exact approved offline initializer is Q020's decision; simply calling load_world does not prove the player is fully playable.

Frame dependency is `main -> updateworld -> due scripts, syncentchanges, physicsframe, updateoutbreak, weapon/shoot, bounce/remote movement, gets2c, BotManager.Think if botmode, movelocalplayer, c2sinfo`, followed by `serverslice`, audio and render; render also calls WaypointClass.Think. Offline map proof needs input, collision/movement, view/render and initialized player state; no bots, flood/path work, shooting/down/revive, match validation or demos are required. Existing combat experiment remains protected and must be gated by a future authorized ticket, not removed here. Network client may retain local movement prediction/presentation after a frozen contract; it must not apply authoritative damage/AI merely to satisfy legacy calls.

Prevent legacy traffic at entry points AND lower-level services: no native connect/lanconnect/modconnect path, resolver init/queries, master listing or serverms registration, package updater/download queue, credential/config-directory import, delayed assaultcube:// connection, or service-triggering autoexec/autostart/menu hooks. Use a curated profile/config manifest, not arbitrary stock saved/user configs. Content absence must produce a file/error report, not a fallback network fetch or fake success. No such prevention has been executed or verified by T020.
